# 同时推进多件事

::: say
> 问一下正在跑的部署对话现在进展如何

Halo 会在当前工作区里找到那个对话，把问题发过去，等它回答后把进展告诉你。那边收到的消息标着「来自对话」，不会被当成你本人说的话。

**前提**：两个对话在同一个工作区里。这项能力默认开启，不用额外设置。
:::

## 同时开几个对话和工作区 {#several-conversations}

一个对话在工作时，你可以去做别的事。切换对话或工作区不会打断正在进行的回复，回复会在后台继续写完。

1. 在对话列表顶部点 **新对话**，开始第二件事。第一个对话照常运行，列表里它旁边的蓝点表示还在工作。
2. 想换到另一个项目，点顶栏左侧的工作区名称（提示「当前工作区：… · 点击切换」），在下拉列表里选一个工作区。列表按最近使用排序，[Halo 工作区](/features/spaces#halo-workspace) 固定在最上面。
3. 回到任意一个对话，都能看到它此刻的进度，包括还在写的回复。

每个对话单独选模型，所以可以一个对话用快的模型查资料，另一个用强的模型写代码。看 [模型与账号](/features/models#model-per-conversation)。

每个工作区有自己的一组画布标签页。切换工作区时，画布换成那个工作区的标签页；没保存的修改和正在运行的终端都会保留，切回来还在。画布的用法看 [文件与画布](/features/files-and-canvas)。

关掉窗口，工作也不会停：在 macOS 和 Windows 上，窗口会缩到托盘，对话和数字人继续运行。Linux 上关窗口会退出 Halo，正在做的事也会停下，详见 [关闭窗口后继续运行](/features/tasks#window-closed)。

## 活跃会话数量上限 <Badge type="info" text="仅桌面版" /> {#active-limit}

Halo 会让最近用过的一批对话保持随时可答。每个常驻会话（包括数字人、IM 和团队成员的会话）在内存里占一个 AI 进程。**设置 › 高级 › 活跃会话数量上限** 决定最多保留多少个。

| 项目 | 值 |
|---|---|
| 范围 | 2–50 |
| 默认 | 20 |
| 超过上限时 | 最久没用的空闲对话先暂停，你下次给它发消息时自动恢复，内容不会丢 |
| 正在回复的对话 | 不会被暂停。所有对话都在忙时，新的对话照样开始，暂时超过上限 |
| 内存紧张时 | 系统可用内存低于 15% 时，上限自动减半 |

电脑内存小、经常同时开很多对话时，可以把上限调低。各项设置的完整说明看 [设置参考](/features/settings#limits)。

## Halo 工作时继续补充 {#add-while-working}

不用等 Halo 说完。它工作时你可以接着打字、接着发，发送按钮这时显示「加入队列」。

1. 写下补充，比如「数据只要华东区的」，按发送。消息出现在正在进行的回复下方，标着 **已排队**。
2. Halo 做完手上这一步就会读到它，标记变成 **已附加**，并按新要求继续。

排队的消息不能带图片，也不能修改或撤回。在 Halo 读到之前按了停止，它会标成 **已停止，未处理**，不会执行。细节看 [会话 › Halo 工作时继续补充](/features/conversations#queue)。

## 跟进每件事的进度 {#follow-progress}

不用挨个点开对话。两个地方能一眼看清：

- **状态点**：对话列表每一行前面的小圆点。

  | 颜色 | 意思 |
  |---|---|
  | 蓝 | 正在工作 |
  | 琥珀 | 等你回答问题 |
  | 绿 | 已完成，你还没看 |
  | 红 | 出错 |
  | 没有点 | 空闲 |

- **任务面板**：点导航栏底部的 **任务**。所有工作区里的事都在这一个列表里，分成 **需要你处理**、**运行中** 和 **已置顶** 三组。点一行就回到那件事，必要时会自动切换工作区。看 [任务面板](/features/tasks)。

想在 Halo 窗口不在前台时收到「任务完成」的系统通知，要先打开 **设置 › 系统 › 任务通知**，它默认关闭。看 [任务面板 › 通知](/features/tasks#notifications)。

## 问其他对话的进展，或把结果交过去 {#ask-other-conversations}

同一个工作区里的对话可以互相沟通。直接告诉 Halo 你想做什么：

- 问进展：「问一下正在跑的部署对话现在进展如何」
- 交结果：「把这个结论告诉『前端改版』那个对话」
- 查结论：「看看『数据库选型』那个对话最后定了什么」

也可以在输入框点 **＋ › 上下文 › 引用会话**，或输入 `@`，选中要引用的对话。

对方正忙时，消息会等它做完当前这一轮再送到。Halo 默认最多等 120 秒回复（最长 300 秒），等不到会告诉你还没有回音。不同工作区的对话之间不能互相发消息。规则、频率限制和数字人对话的开关，看 [会话之间互相协作](/features/cross-conversation)。

## 把大活交给团队 {#hand-to-a-team}

一件事可以拆成几块并行做，或者需要有人专门复核时，让 Halo 组一个临时团队。

::: say
> 组个小团队：一个调研、一个写稿、一个审稿，帮我出一份竞品报告

Halo 会组建一个 1–5 名成员的临时团队，自己担任协调，成员在后台分头工作。对话底部出现「团队：名称 · 2/3 个工作中」面板，每位成员一行，带状态点。成员的汇报会出现在对话里，标明是团队成员发送的。

**前提**：输入框 **＋ › 能力** 里的 **团队协作** 打开着。新对话默认就是打开的（如果你之前关过，新对话会沿用你上次的选择）。
:::

- 点面板上的 **打开团队视图**，在画布里看团队的进展。
- 一个对话同时只能有一个临时团队。想以后接着用这支团队，点团队视图顶部的 **保留此团队**。
- 当前工作区里已保留的团队可以直接派活：「把这个需求交给竞品团队」。

团队怎么分工、怎么回答成员的提问，看 [数字人团队](/digital-humans/collaboration)。

## 固定的活交给数字人 {#recurring-work}

每天、每周都要做的事，不必每次开一个对话。交给 [数字人](/digital-humans/overview)：它按计划或在事件发生时自己运行，结果汇报给你，不占用你正在用的对话。等你决定的问题会出现在任务面板的 **需要你处理** 里。怎么设定运行时间，看 [运行计划与触发方式](/digital-humans/triggers)。

## 好用的分法 {#patterns}

| 做法 | 为什么 |
|---|---|
| 一个项目一个工作区 | 文件、记忆、数字人按项目分开，问「部署对话」时不会找错 |
| 按主题分对话，不按步骤分 | 同一件事的来龙去脉留在一个对话里，Halo 不用反复读别的对话 |
| 耗时长的工作单独一个对话 | 部署、批量处理这类长任务不会被别的问题打断；需要时再问它进展 |
| 能并行的大活交给团队 | 调研、写作、审稿同时进行，你只看汇报和需要你决定的事 |
| 重复的活交给数字人 | 按时自己运行，不必记着去发消息 |
| 不用一直盯着 | 看状态点和任务面板就知道哪件事需要你 |

## 限制与成本 {#limits}

同时推进的事越多，消耗也越多。

| 项目 | 说明 |
|---|---|
| 模型用量 | 每个正在工作的对话、团队成员和数字人都在调用模型，各自消耗 token |
| 数字人同时运行 | 整个 Halo 最多 10 个，多出的按顺序排队，任务面板显示「已排队」 |
| 同一位数字人 | 一次只运行一个 |
| 计划任务同时启动 | 到点的计划任务一次最多启动 5 个 |
| 团队成员同时工作 | **设置 › 高级 › 数字团队并发限制**，默认 10，范围 1–100 <Badge type="info" text="仅桌面版" /> |
| 对话常驻数量 | 见上文 [活跃会话数量上限](#active-limit) |

数字人的运行规则看 [运行记录与管理 › 运行限制](/digital-humans/manage#limits)。

::: done
对话列表里几个对话旁都有蓝点，任务面板 **运行中** 里列着它们，就说明这几件事在同时进行。
:::

## 遇到问题 {#troubleshooting}

### Halo 说找不到我要问的那个对话

对话之间只能在同一个工作区里沟通。先切到那个对话所在的工作区，再问一次。对话标题有重名时，Halo 会列出候选让你选。

### 开了很多对话后，电脑变慢了

每个常驻的对话都占内存。在 **设置 › 高级 › 活跃会话数量上限** 里把上限调低，最久没用的空闲对话会先暂停，下次发消息时再恢复，内容不会丢。见 [活跃会话数量上限](#active-limit)。

### 数字人的运行一直显示「已排队」

整个 Halo 同时最多运行 10 个数字人，同一位数字人一次只运行一个。等前面的运行结束，它会自动开始。

### 补充的消息没有被执行

在 Halo 读到它之前按了停止，消息会标成 **已停止，未处理**。重新发一次即可。

### 关了窗口，工作停了

在 Linux 上关窗口会退出 Halo。想让工作在后台继续，保持窗口开着（可以最小化）。
