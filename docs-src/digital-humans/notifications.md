# 通知与主动推送

::: say
> 把这份周报总结发到「市场部群」。

在数字人自己的聊天里说，它会把消息推送到那个群；在 Halo 的 **IM 会话** 里，这条消息上方标着「主动发送」。**前提**：这个群在它的 **可联系的联系人** 里，见 [主动发给联系人](#push-to-contacts)。
:::

## 两种发出去的方式 {#two-ways}

| | 主动发给联系人 | 单向通知通道 |
|---|---|---|
| 发给谁 | 给数字人的机器人发过消息的人和群 | 邮箱、企业微信应用、钉钉、飞书应用或 Webhook 里设好的接收人 |
| 对方能不能回 | 能，回复由数字人接着处理 | 不能 |
| 在哪里设 | 数字人的 **能力与设置 › 消息与通知** | **设置 › 消息通道** 下半部分的单向卡片 |
| 需要的能力 | **IM推送**（默认开着） | 至少开着一个通知通道 |

两种都由数字人自己判断什么时候发、发什么。想让它固定在某个时候发，写进它的 **系统提示词**，比如「每次运行结束后，把结论发到市场部群」。

## 主动发给联系人 {#push-to-contacts}

1. 先给数字人接好机器人，见 [消息通道概览](/digital-humans/channels)。
2. 让要接收的人或群先给机器人发一条消息（群里要 @ 机器人）。他们会自动出现在数字人的 **能力与设置 › 消息与通知 › 可联系的联系人** 里。
3. 给联系人 **重命名**，起一个好认的名字，比如「市场部群」。你说「发到市场部群」，它就知道是哪个。
4. 在数字人的聊天里让它发，或者写进它的工作说明。

几点规则：

- 它不会往当前正在对话的聊天里「推送」，那里本来就会收到回复。
- 发出去的文件只能来自它的工作区或临时文件夹。
- 机器人的访客默认不能让它给别人发消息，见 [主人与访客权限](/digital-humans/permissions#guest-limits)。
- 微信在 Halo 重启后，要对方先发一条消息才能再发。

### 每次运行后自动同步结果 {#auto-sync}

在 **可联系的联系人** 里给某个联系人打开 **自动同步运行结果**，每次运行成功后，最终回复会自动发给这个联系人，在 **IM 会话** 里标着「主动发送 · 运行结果」。默认关闭。

### 借用别的数字人的机器人 {#from-existing-chats}

**从已有会话添加** 可以让这位数字人往另一位数字人的机器人认识的聊天里发消息，这些聊天会标着「从其他机器人添加」。那边的人回复时，仍由原来的数字人处理。不想再发了，点 **停止推送到此会话**。

## 单向通知通道 {#one-way-channels}

在 **设置 › 消息通道** 的下半部分，每张卡片都有 **已启用** 开关、要填的字段和 **测试** 按钮（要先启用才能测试）。设好一次，所有数字人都能用。

| 通道 | 要填的 | 说明 |
|---|---|---|
| **电子邮件** | **SMTP 主机**、**SMTP 端口**、**使用 SSL/TLS**、**用户名**、**密码**、**默认接收者** | 密码一般填邮箱的「应用密码」或授权码。**测试** 只检查能不能登录，不会真的发信。见 [邮件与日历](/features/email) |
| **WeCom**（企业微信应用） | **企业 ID**、**AgentId**、**密钥**，可选 **默认用户 ID**、**默认部门 ID** | 不填 **默认用户 ID** 时，即使填了 **默认部门 ID**，也会发给企业里的所有人 |
| **DingTalk**（钉钉） | **App Key**、**应用密钥**、**AgentId**，可选 **RobotCode**、**默认聊天 ID** | 填了默认聊天 ID 就发到那个群，否则给所有人发工作通知 |
| **Feishu**（飞书应用） | **应用 ID**、**应用密钥**，以及 **默认聊天 ID** 或 **默认用户 ID** 二选一 | 接收人至少填一个；两个都填时发到 **默认聊天 ID** |
| **Webhook** | **URL**，可选 **请求方法**、**请求头（JSON）**、**HMAC 密钥** | 以 JSON 发送标题和正文；填了密钥时带 `X-Halo-Signature` 签名。**测试** 会真的发一条 |

中文界面里，**WeCom**、**DingTalk**、**Feishu** 三张卡片显示的就是英文名。企业微信、钉钉、飞书的 **测试** 只验证凭据能不能换到令牌，不检查接收人对不对。

::: warning 钉钉和企业微信默认发给所有人
钉钉不填 **默认聊天 ID**、企业微信不填 **默认用户 ID**（只填部门也一样）时，通知会发给公司里的所有人。让数字人发之前，先填好接收人。
:::

## 桌面通知 {#desktop}

- 每位数字人的 **消息与通知 › 系统通知**：**重要**（默认：里程碑、提问和产出）、**全部**（每次运行结果）或 **无**。
- 窗口不在前台时，Halo 弹系统通知；在前台时，显示应用内的提示。
- 普通会话在后台完成时要不要通知，在 **设置 › 系统 › 任务通知** 里设，默认关闭。

::: done
联系人收到了数字人发的消息；在 Halo 的 **IM 会话** 里，这条消息上方标着「主动发送」。
:::

## 遇到问题 {#troubleshooting}

### 它说找不到「市场部群」

这个群还没出现在 **可联系的联系人** 里。让群里的人先 @ 机器人发一条消息，再把它重命名成好认的名字。

### 通知通道测试通过了，但没收到

企业微信、钉钉、飞书的测试只验证凭据，不检查接收人。核对 **默认用户 ID**、**默认聊天 ID** 是否正确；电子邮件的测试也不会真的发信，可以让数字人发一封试试。
