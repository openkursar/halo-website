# 核心理念

## Kill Ugly Raw Source, AI Rewrites

这是 Halo 的创始哲学，也是它名字背后真正的含义。

最初，这句话指的是用 AI 重构糟糕的代码。今天，它的边界已经远远超出了代码本身——它指向数字世界中一切原始、低效、需要人工重复介入的事物。

我们相信：**凡是能被 AI 自动处理的，就不该再占用人的注意力。**

---

## Halo 的故事 {#story}

### 从一个问题开始

2025 年 10 月，cursor 调整了会员策略，编程成本骤增。那段时间，我们反复在问一件事：

> 有没有一款工具，既具备 Claude Code 那样强大的 Agent 能力——**但随时随地远程操作电脑桌面**、**驱动 AI 浏览器自主完成任务**，同时又有友好的可视化界面，**文件管理、产物预览**一应俱全，让开发者和产品人都能直接上手？

我们做了市场调研，结论很清晰——不存在。市面上要么是 Open Web UI、LobeChat 这类能自定义 API 的聊天工具，要么是 Claude Code CLI、Gemini CLI 这类极客向的终端交互。

没有我们想要的东西，就自己做。

### 一个周末的诞生

我们花了一个周末，用 Claude Code 实现了 Claude Code 自己的可视化桌面。第一个版本同时支持 macOS、Windows、Linux、Web 四端，约 95% 的功能开箱即用。

更不可思议的是：从那以后，Halo 100% 的代码都由 AI 自己生成，我们再也没有打开过 Cursor 或官方 CLI。

几个月后，市面上出现大量类似的 Cowork / xxClaw。Halo 是最早一批将远程指挥 + 完整 Agent 能力带到普通桌面的客户端。

### Halo 的目标

**Halo 不追随热点，只追求效率。**

我们聚焦一件事：提升个人与组织的运转效率，消除一切人工与等待。

市面上的概念和热词换得飞快，我们既不追逐，也不与之比较。Halo 100% 由 Halo 自身构建，这本身就是一次效率边界的探索：我们不参考、不跟随任何外部概念，因为我们相信——

> 最好的方向，来自个人与团队最直接的反馈，来自效率本身的反馈；而不是任何概念的演化与改良。

市面上的名词每天都在变。我们只问一个问题：**它有没有让人更快、更省心。**

## 关于 Halo 是如何开发的

Halo 是一个关于 AI 生产力的活体实验。它的第一个版本诞生于 2025 年 10 月的一个周末，从那以后，100% 的代码（几十万行）由 Halo 自己生成，没有打开过任何其他 IDE。

这不是噱头，而是一个严肃的工程实践验证：

1. **阶段一（人类核心价值）**：花 2–4 小时与 AI 深入讨论设计、架构、技术栈，细化到目录结构，形成数千字的完整开发计划。架构决策是人类最不可替代的贡献。

2. **阶段二（AI 执行）**：把开发计划交给 AI，喝一杯咖啡。

3. **阶段三（验收）**：约半小时后，几十乃至数百个文件全部就绪，`npm run build` 编译通过，就能启动跨四端的桌面应用。

Halo 的架构融合了 VS Code 的分层设计理念，同时抽象了 Agent 的可插拔性，支持 Web / Windows / macOS / Linux 多端共用渲染层。

> 传统人力可能需要一个团队数月、数年。借助顶级 AI 模型，一个人可以在一个周末完成同等工作。这是工业革命式的效率跃迁——机器出现后，一个司机就能驾驶火车运载上万斤货物。

## 我们的立场

**Halo 不是商业产品。** 它是个人与社区兴趣驱动的开源项目，致力于在业余时间探索 AI Agent 的更多可能。

我们认为，未来的计算平台不应只是提供 Copilot 工具，而应该提供一个标准化的运行时环境，让 AI 智能体能够**持久化、自主化**地接管复杂业务流。这一切应该是开放的、可共建的，不该被商业公司垄断。
